[The Problem]

UltimaV has TWO scales for tiles - Overworld, and Town/City.  In either case, each tile is the same visual and world size - 1 tile.

The player uses their imagination to rescale everything appropriately IN THEIR HEAD.


For biome tiles, this can make perfect sense. But we also have a bridge being the same size as a keep, or a signpost, or a cactus, or dungeon entrance.

These overworld tiles are often overly simplistic representations of whats really there.  So let's ignore them.

The "town/city" tiles - these are much more meant to represent the actual detailed architecture and furniture of a place - and are much closer to the "real" scale that an individual player navigates.

Same problem though e.g. a wall mounted torch is the same size as a wardrobe, a staircase, a lamppost, a harpsicord etc etc

However in Valheim, a 3D game, all assets have a variety of sizes and there IS no rescaling - scale is expected to be 1:1.


(also note some tiles exist in both scales, e.g. the biome tiles, bridges, rivers - they represent the same concepts, but at very different scales, when that happens.)

[A Note On Elevation]

Just because there's a maximum elevation height, doesn't mean we have to use it. I have noticed that mountains and peaks tend to just shoot straight up.  a SLIGHTLY more managed ascent to the heavens would look better and let's not feel we have to reach ALL the way to the maximum height.

The existence of waterfalls implies the existence of discontinuties in the height of a bit of land that water is travelling over.  So if you need to place cliffs anywhere (a cliff being said discontinuty), try using the location of these waterfalls (tiles 212 - 215) as a guideline.

[Solution A] (recommended)

We create a standard scale mapping for ultima overworld scale tiles: 1 tile -> 32m x 32m x 3m

Most towns and cities are 31x31 so this actually a great scale mapping.  obviously when mapping a "representative" tile like a town icon, we don't use 32x32x3 metres to make a singular icon - we delve into the plan of the actual town and render it at a different scale.

And obviously that scale WOULD be 1m x 1m x 3m.  This turns out to be awful.  Make it 2m x 2m x 3m instead.  This means that when placing a town somewhere, it will likely spill over into other "tiles" in the overworld.  Not a big deal, we are big boys and can shuffle things around to make it all fit.

PRO: A true 1:1 mapping from the Ultima files to the Valheim world can now be made.  This would be almost effortless.

CON: Everything needs be squeezed into a 2m x 2m x 3m shape.  Getting that right could take a bit of work - and worse - it's going to look like Minecraft.

If using this solution, see "Tile Mappings" section below


[Solution B]

We describe each town's layout and content and furniture, and then make Valheim appropriate buildings from those descriptions.

PRO: Should look a lot more "Valheimy" and everything can have their natural Valheim dimension.

CON: Will not exactly resemble the original towns.  In some rare cases this might break quests -> we can deal with that on a case-by-case basis I reckon.  Will be relying very heavily on AI to create complex 3D assets !!!  This will use a vast amount of tokens.


[Solution C]

The AI can place the foundation of each town down into the world. The human developer then builds each town using valheims in-game construction system.

PRO: Each town can be built exactly how the human likes it.  No tokens will be harmed, and if a random rule needs to be broken to add flair or whatever, lo, it can be done.  Issues will be fixed on the fly.

CON: This will take ages and suck all the fun out of "discovering" a new place, because it won't be new will it ?  You'll know every nook and cranny cause YOU BUILT IT. Only applies to the human that built everything.  All other players can still enjoy it - months down the track of course.

[Tile Mappings - Town/City/Castle (i.e. indoors)]

Once we're at the 2m x 2m x 3m style scalings inside a town like Britain, for example, we have different tiles to consider.

NOTE: "Overworld" tiles can still appear in towns, especially biome tiles !  These often need a second mapping attached to make sense in a smaller scale, and especially in a settlement environment.

- Height Zones

There is a ground zone. the top of all floor tiles should be in the same plane. it should roughly match ground-level.

Atop the ground zone is the wall zone.  it extends 3m upwards from the top of the floor zone.  All walls and furniture and loose objects live here.

For multi-story buildings, there is the inter-level zone. Floor pieces go here - the top of every floor piece is in the same plane as the top of the wall zone under it.  Keeps the maths tidy.  Obviously you then add another wall-zone above that inter-level zone.  Keep repeating for every story.

CAUTION: Some multi-story constructions will try to tell you to put stone flooring in the inter-level floors.  This is nigh on impossible.  Use wood instead.

- Roofs

Once we run out of extra floors, we enter the roof zone.  the bottom of the roof zone is also the top of the wall zone.

Cobblestone walled cottages get thatched roofs (wood)
All other town/village structures get shingled roofs (shingle)
Castle/keep/tower/lighthouse structures get grausten roofs (grausten)
